## 转做 DLL 补丁（patcher，用户否决"改本体/单独包体"，要求插件仓库形式）

- 结论：预览弹窗在 `App.Init()` 早期 `await FATaskDialog.ShowAsync()` 模态阻塞，插件在 Host 构建后才加载 → **标准 .cipx 插件无法拦截**（用户最终接受"补丁"形式，选了 patch+文档，后又升级为"可运行的 dll patcher"）。
- 方案：**Mono.Cecil 二进制补丁**——patcher 直接改已安装的 `ClassIsland.dll`，免编译、可逆（自动备份 .bak）。
- **弹窗 IL 结构（关键）**：弹窗在 `ClassIsland.App/<Init>d__67::MoveNext()`（async 状态机方法，非 Init 本身）。IL 从 `newobj FATaskDialog` 开始，一系列 `set_*`，`callvirt ShowAsync`，await 完成是 `GetResult`→`pop`。**patch 只把开头的 `newobj` 替换成 `br <弹窗后第一条指令>`**，一条指令搞定，栈平衡/状态机不受影响。
- 定位方法：`ldstr "欢迎使用 2.2-Misha Developer Preview"`（唯一 marker）→ 向前找最近 `newobj`（FATaskDialog 构造，起点）→ 向后找 `ShowAsync` callvirt → 再找 `GetResult`（await 完成）→ 终点 = GetResult 后的 pop 之后。
- **Mono.Cecil 坑**：①`ReadAssembly(path)` 默认持有文件流（FileShare.Read），直接 `asm.Write(同路径)` 报"文件被占用"→ 写临时文件 + `asm.Dispose()` 后 `File.Copy` 替换；②Write 时需解析依赖（报 `Failed to resolve assembly: Avalonia.Base`）→ `ReaderParameters.AssemblyResolver = DefaultAssemblyResolver` 并 `AddSearchDirectory(dll所在目录)`（用户场景安装目录依赖齐全，但 Library 的 bin 目录依赖不全会失败）；③`MethodBody.OptimizeMacros()` 在 `Mono.Cecil.Rocks` 命名空间，直接调会 CS1061，去掉即可（br 长形式合法）。
- patcher 发布：`dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o dist` → 单文件 37.8MB。中文输出乱码 → `Console.OutputEncoding = UTF8`。
- 交付物位置：`IslandCallerTopmostEnhancer_reclone/classisland-2.2-skip-preview-warning/`（README + .patch + patcher/源码）。已 commit 1589df4、c6fd4a9，待 push（需 PAT）。
- 插件仓库 remote = github.com/1sIancl/IslandCallerTopmostEnhancer.git；远程 main 实际已到 820b6bc（本地 reclone 的 origin/main 是 stale，fetch 后仍 ahead 假象，以 `git ls-remote` 为准）。

## Classcaller 液态玻璃修复（14:49 起，重点）

- 需求：修复液态玻璃样式存在的问题（设置页红字警告的「严重内存泄漏 + use-after-free → 崩溃/BSOD」）。
- **MorerialsAvalonia 1.1.0 库架构**（用 Mono.Cecil 反编译 dll 确认）：`MaterialHost`（每 TopLevel 一个，静态 `ActiveHosts` ConditionalWeakTable）→ `MaterialBackdropSurface`（模板内 GPU 层，`_activityTimer` DispatcherTimer）→ `DesktopCaptureService`(DXGI Desktop Duplication) → `D3D11MaterialRenderer`。清理依赖 `OnDetachedFromLogicalTree`→`StopHostSession`（Dispose renderer/surface/compositor）。`InitializeComposition` 是 **async void**（Loaded 优先级 Post）。
- **根因一（use-after-free/内存泄漏）**：`HoverLiquid`/`LiquidShower` 订阅 `Materials.Diagnostics.PropertyChanged` **从不反注册**，窗口关闭后 MaterialHost 后台渲染线程仍通过诊断回调访问已销毁窗口。修复：两者覆盖 `OnClosed` 反注册 + `Content=null` 主动 detach。
- **根因二（展示窗口渲染失败，关键）**：两个液态玻璃窗口同时存在会**争抢 Desktop Duplication 捕获会话**，后创建的 LiquidShower 每次 `AcquireNextFrame` 报 `E_INVALIDARG`/`NullReferenceException`（CaptureState 卡「等待/error」，IsOperational=False）。设置页描述早有提示「悬浮窗和展示窗口只有一个能为LiquidGlass」，但代码 `CanUseHoverTheme/CanUseShowerTheme` **从未实现互斥**。修复：`LiquidGlassRuntime.CanUseShowerTheme` 加互斥（悬浮窗优先，HoverTheme==1 时展示窗口回退 Fluent）。
- **根因三（内存泄漏主源）**：库的 Desktop Duplication/D3D11 资源在窗口 Show/Hide（occlusion pause 暂停→恢复）循环中泄漏，且 Avalonia `Window`/`TopLevel` **不实现 IDisposable**（无法 Dispose 释放），每次点名 new+Close 展示窗口泄漏 ~40MB。修复：①**复用展示窗口**（`GetOrCreateShowerWindow`，主题变化才重建，Show/Hide 而非 Close）；②**禁用 `EnableOcclusionPause`**（避免暂停→恢复循环重分配资源）。
- **实测数据（内存，ClassIsland.Desktop 进程 WorkingSet）**：修复前每点名 ~40MB（10 次 405MB）；复用窗口后 ~4.6MB/次；复用+禁用 occlusion 后稳定 ~2.2MB/次（约 18 倍改善）。互斥生效后场景 A（双液态玻璃）0 错误，场景 B（仅展示液态玻璃）`IsOperational=True`。
- **关键经验**：①`LiquidGlassContainer.CornerRadius` 是 **double**（非 Avalonia CornerRadius 结构），`new CornerRadius()` 报 CS0029；②MorerialsAvalonia 依赖 `RenderingMode=AngleEgl`+`CompositionMode=DirectComposition`；③`EnableOcclusionPause=False` 副作用是窗口隐藏仍捕获桌面（GPU 开销，但换内存稳定）。
- 测试环境：`ClassIsland2_publish/`（self-contained 2.2），插件目录 `Plugins/Classcaller/`，注册表 `HKCU\Software\Classcaller`（Hover/HoverTheme、Call/ShowerTheme、Call/NotifyMethod 需=3 才显示展示窗口、Call/BaseTime+AdditionalTime 控制时长）。触发点名用 PowerShell `Start-Process "classisland://plugins/Classcaller/Simple"`（cmd //c start 不可靠）。日志 `Logs/log-*.log`。
- 产物：`Classcaller.cipx`（MD5 9fbbbb2dc3ed8cd2772a08438049cb77）。
